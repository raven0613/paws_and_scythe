# 核心遊戲流程與關卡數值

本版使用 Godot 與 GDScript，從 `src/nodes/gameplay.tscn` 開始遊戲。啟動後直接以零張貓牌與起始金錢挑戰 Lv 1～21，每關重新洗混標準 52 張牌、抽六張手牌並重建牌陣。Lv 1～20 過關後顯示 [過關獎勵](level_reward.md)，接著進入 [商店](shop.md) 購買或賣出貓牌，按下一關繼續；貓牌跨關保留。Lv 21 達標後顯示通關，敗北與整場通關提供重新開始，重新開始回到零張貓牌與起始金錢。

測試入口由 `src/configs/gameplay/test_entry_config.gd` 的 `SHOW_TEST_ENTRY` 決定是否顯示，預設關閉。開啟後按鈕位於畫面右上角，操作階段可按。按下後開啟三十張貓牌的複選畫面，選擇零至五張並按「開始」，以所選貓牌與起始金錢從 Lv 1 開始新的一場；按「取消」回到目前的遊戲。

## 狀態與責任

`src/service/gameplay/run_state.gd` 管理一場遊戲的牌庫、手牌、牌陣、操作歷史、費用、額度與關卡判定。卡牌以唯一 ID 表示，`cards.gd` 負責 ID 與花色、牌面點數及計分點數的對應，`deck.gd` 負責洗牌、抽牌與棄牌堆回收。`poker_patterns.gd` 辨識連續格子內的撲克牌型，`scoring.gd` 按牌型階級、長度及固定位置選出同方向互不重疊的分組，再合併橫直方向，依原始分數由高到低、同分時橫向在前及牌型第一格位置排出 Combo 清單，並計算 Combo 與新出高牌保底分，同時依上排左至右的閱讀順序列出每張高牌的格子與點數，供結算演出逐張呈現。牌型分數為參與卡牌點數總和加上牌型達成分數；交叉牌在兩個方向各加一次點數，新出未參與牌型的牌依自身點數提供高牌保底。階級、點數與達成分數分別由 `game_rules.gd` 的 `HAND_ORDER`、`RANK_POINTS`、`HAND_BONUSES` 設定。貓牌的辨識修正先傳入候選選取，辨識後由 `service/cat_cards/cat_resolver.gd` 決定得分資格、套用效果並產生逐步事件。預覽、演出與正式結算共用同一份計算結果，貓牌模組責任見 [貓牌系統](cat_card.md)。

`src/scripts/gameplay/gameplay.gd` 將遊戲狀態接至現有場景，依卡牌 ID 重用 `playing_card` 實例。測試入口選牌、貓牌排序與結果畫面由各自的元件處理，`economy_presenter.gd` 串接過關獎勵、商店、貓牌買賣與金錢顯示，`settlement_presenter.gd` 讀取結算事件，串起來源貓牌、目標分數、Combo、粒子與入帳。演出期間鎖定遊戲操作，完成或跳過時提交確認時保存的快照一次，詳見 [結算分數演出](settlement.md)。

## 操作與確認

點擊手牌切換選取狀態，可同時選取多張，選取的牌向上位移；按下後未拖曳就放開才算點擊。放牌可選取一張後點擊待放格，或按住手牌移動超過 `card_drag_config.gd` 的 `START_DISTANCE` 拖曳到待放格放開。拖起手牌時清除原有選取與場上操作模式，由 `src/scripts/hand_area/card_drag.gd` 接手卡牌，放開後由 gameplay 交給核心放牌，成功時拍入格子，其餘情況飛回原手牌槽位。空盤直接顯示中心待放格；已有卡牌時，本次仍有出牌額度、場上未達容量上限，且恰好選取一張或正在拖曳時才顯示合法待放格。出牌、取消選取、切換場上操作模式或選取多張時收起，顯示與收起使用透明度和縮放補間。選取一至三張手牌後按棄牌，立即替換原槽位並消耗一次本關棄牌額度。

按挖牌後點選場上卡牌即挖除；按交換後依序選取兩張場上卡牌，點同一張可取消第一個目標。實際分數足夠支付且仍有額度時可連續操作，成功後立即扣分；分數、有效牌數或額度不足時回到放牌模式。按相同模式按鈕、選取手牌或按 Esc 也可回到放牌模式。操作按鈕呈現當前模式與剩餘次數，目標提示顯示單次費用。

放牌、交換與挖牌記錄在同一個後進先出操作歷史中，撤銷一次還原一個操作。撤銷放牌恢復原手牌插入位置；撤銷交換和挖牌同時恢復牌位與額度，並依操作歷史記錄退回各次實際支付的費用。棄牌與補抽立即確認，後續撤銷其他操作時仍保留已補抽的手牌和已消耗的棄牌次數。

待確認的挖牌保留於操作歷史，確認結算時移入可回收的棄牌堆。如此在挖牌後執行棄牌補抽時，抽牌來源維持為抽牌堆及已確認的棄牌堆，而撤銷挖牌可還原同一張實體牌。所有狀態下，手牌、場上牌、抽牌堆、棄牌堆與待確認挖牌的總數均為 52，且 ID 唯一。

核心分數完整保留貓牌與 Combo 計算的浮點精度，累積分數、中央分數與結果分數統一四捨五入顯示整數。交換與挖牌以已累積的實際分數支付，分數保持非負；開局零分時使用免費復原調整出牌。結算依序套用逐組貓牌、額外計分、整次加分、Combo 與總分倍率，操作費用在操作時支付。場上張數達到容量上限時核心拒絕放牌，挖牌騰出空位後可再放；結算補牌後若場上已滿且累積分數不足以支付挖牌，玩家無法再出牌，判定敗北。過關優先於所有敗北條件。

每場起始金錢由 `game_rules.gd` 的 `STARTING_MONEY` 設定，跨關保留，重新開始時重置。`run_state.gd` 在過關時計算並入帳過關獎勵，並負責開店、購買、重骰與賣出的資格判定及金錢收付；商店的上架內容由 `service/shop/shop_state.gd` 保存，使用獨立於牌庫的亂數。核心抽牌透過 `last_draw` 提供每張實際抽出的卡牌與剩餘牌數，畫面使用同一個發牌流程呈現開局、跨關及補抽。金錢顯示與發牌場景詳見 [鏡頭控制、牌庫與金錢](gameplay_controls.md)。

`tests/gameplay/curve_probe.gd` 是調整目標時的參考工具。探針以 `cat_balance_config.gd` 的四條構築路線各搭配兩種花錢策略與八個固定種子，共 64 位模擬玩家，從零張貓牌與起始金錢開始逐關遊玩。每關以目前持有的貓牌量測六次結算的累積分數，取全體第 N 次結算累積分數的中位數作為該關的建議目標；N 由 `curve_probe_config.gd` 的 `CLEAR_TURNS` 設定，建議目標依同檔的取整單位取整，相鄰關卡至少增加一個取整單位。模擬玩家依建議目標下實際達標的結算次數領取過關獎勵，再依路線順序購買下一張貓牌；spend 策略買得起就買，save 策略保留可拿滿利息的 20 元，只花超出的部分。探針假設商店總能提供路線上的下一張貓牌，玩家不重骰也不賣牌。每關輸出建議目標、中位持有張數與金錢、未達標比例、中位達標結算次數及各次結算的中位累積分數，最後一行列出完整的建議目標陣列。

`tests/gameplay/balance_probe.gd` 量測零貓牌基線。`tests/cat_cards/balance_probe.gd` 以四種構築、零至五張卡牌與每種八個固定種子，量測六次結算的完整產出。出牌策略由 `tests/support/probe_player.gd` 提供，與曲線探針共用：每次出牌量為 5、4、3、3、2、2，總共十九張；棄牌偏好保留相同點數，放牌選擇含貓牌加成的即時最高分落點，計算時使用補牌前實際剩餘手牌。探針在提早達標後繼續量測完整資源產出，並列出第三至第六次結算的中位累積分數。

## 核心驗證

`tests/gameplay/scoring_test.gd` 覆蓋牌型、跨越 K-A-2 的環狀連號、所有起點與支援長度、延伸牌型、階級優先、同級取長與固定位置決勝、各牌面點數、橫直交叉點數、孤島、清單依原始分數與同分位置排序、無關牌連到牌列時維持順序、高牌保底、逐張高牌依閱讀順序列出且點數總和等於保底分，以及高牌參與倍率；`deck_test.gd` 覆蓋完整牌庫、固定種子洗牌與回收；`run_state_test.gd` 覆蓋零分與不足額拒絕、實際分數付款、即時扣款、原價退費、操作額度、結算入帳、棄牌與撤銷交錯、滿格拒絕放牌與挖牌後再放、滿格且付不起挖牌時敗北、關卡重置及最終通關。`invariants_test.gd` 使用固定種子混合操作，驗證卡牌守恆、預覽與結算一致、手牌與出牌限制。`draw_events_test.gd` 驗證起始金錢、跨關保留、重新開始重置及抽牌事件，包含洗回後補抽同一張牌。`tests/level_reward/level_reward_test.gd` 驗證過關獎勵的各項金額、利息與入帳，`tests/shop/cat_market_test.gd` 與 `shop_flow_test.gd` 驗證商店上架機率、價格、重骰與貓牌買賣。這些測試只載入核心邏輯。

貓牌核心另由 `tests/cat_cards/resolver_test.gd`、`run_integration_test.gd` 與 `event_flow_test.gd` 驗證第一批效果、額外計分累加、成長、順序、撤銷與事件精度。`second_batch_test.gd` 驗證第二批條件與交互作用，`resource_state_test.gd` 驗證完整二十一關的操作累積、追溯、撤銷、棄牌重置，以及緊湊貓容量上限的放牌判定與過關優先順序。

可使用 Godot 命令列執行，例如 `godot --headless --path . --script tests/gameplay/scoring_test.gd`；關卡曲線探針執行 `tests/gameplay/curve_probe.gd`，輸出供調整 `LEVEL_TARGETS` 參考的建議曲線。場景啟動檢查使用 `godot --headless --path . --quit-after 30`。
