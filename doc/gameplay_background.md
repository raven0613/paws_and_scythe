# Gameplay 背景與邊框

`src/nodes/gameplay.tscn` 使用 `src/scenes/gameplay_bg/gameplay_bg.tscn` 作為底層，並在上方疊加 `src/scenes/gameplay/gameplay_frame.tscn`。目前製作 `src/assets/bg/01/` 這一種背景，使用 `gameplay_bg_cat00.png` 作為一般方塊，`01`、`02`、`03` 作為三種貓臉。`gameplay_bg.png` 提供排列比例參考；場景以獨立方塊重建排列。

## 排列與移動

參考畫面為 1152 × 648。方塊水平間距為 224 px，每列往下 228 px、向左錯開 16 px，底色為 `#344F71`。貓臉素材比一般方塊多出耳朵與尾巴，繪製時向上偏移 27 px，讓主體與一般方塊對齊。整片背景沿方塊斜率往左下移動，預設速度為每秒 8 個參考畫面像素；位置取整數並使用 nearest texture filtering，保留素材的像素邊緣。

圖樣以固定種子生成環狀排列，移動以欄、列座標分別循環，首尾位置與圖樣保持連續。視窗尺寸變動時，背景與四邊框一起依參考畫面比例縮放。背景節點忽略滑鼠輸入，之後可在 gameplay 上方加入互動元件。

## 貓臉分布

預設連續貓臉上限為 3，每屏至少有 2 個貓臉。連續判定涵蓋同一橫列及相鄰上下列的同一欄；相鄰貓臉使用不同圖樣，所有限制包含循環首尾。一般方塊會中斷貓臉的連續計數。

最低數量透過每個連續 3 欄 × 2 列的區塊保證，背景移動期間也持續成立。這個區塊能完整落在四邊框以內的可見區，因此最低數量以框內完整可見的貓臉計算。此數值是最低數量，實際畫面可以出現更多貓臉；之後疊上的卡牌與介面會依各自位置遮住背景。

生成器先建立符合連續上限與密度的排列，再隨機移除多餘貓臉，保留最低數量，最後加入少量可容許的變化。相同種子可重現相同排列。若調整後的數量限制無法建立有效排列，Godot 會顯示設定錯誤；例如上限為 1 時，六格區塊最多容納 3 個交錯的貓臉。

## 編輯設定

背景設定集中於 `src/configs/gameplay_bg/gameplay_bg_config.gd`：

| 設定 | 用途 |
| --- | --- |
| `MAX_CONSECUTIVE_CATS` | 連續貓臉上限，預設 3，可改為 2 |
| `MIN_CATS_PER_SCREEN` | 框內每屏最低貓臉數，預設 2 |
| `SCROLL_SPEED` | 移動速度，預設 8 px/s |
| `SEED` | 固定分布種子，修改後產生不同排列 |
| `EXTRA_CAT_CHANCE` | 保留最低數量後，額外加入貓臉的機率 |
| `COLUMN_STEP`、`ROW_STEP`、`ORIGIN` | 方塊排列間距與起始位置 |
| `BASE_COLOR` | 背景底色 |

在 Godot 選取 `gameplay_bg`，按 Inspector 的「重新產生背景」可重新載入目前設定並回到起始位置。編輯器預設顯示靜態排列，開啟 `Preview Motion` 可預覽移動，執行遊戲時會自動移動。修改參考尺寸、方塊間距或邊框尺寸時，應一起檢查密度區塊是否仍完整落在可見區內。

邊框設定集中於 `src/configs/gameplay/gameplay_frame_config.gd`。上框厚 34 px、左框寬 37 px、下框厚 30 px，使用 `#151C28` 深色，分別由 `edges/top`、`left`、`bottom` 多邊形節點呈現，尺寸由設定檔更新。右側使用 `edges/boss_bg` Sprite2D 顯示 `boss_bg.png`，位置、縮放與外觀由編輯器設定。整個 `edges` 群組隨場景尺寸一起縮放；`CLEAR_RIGHT_X` 定義背景密度驗證使用的保守可見區右界。

## 核心驗證

`tests/gameplay_bg/background_pattern_test.gd` 驗證不同種子的連續上限、最低貓數、相鄰圖樣差異、循環接縫，以及各個移動位置在框內完整出現的貓臉數；另外確認移動方向、速度與循環座標範圍。
